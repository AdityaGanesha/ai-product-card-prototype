# Черновик карточки прибора

Консольный MVP принимает JSON товара и вызывает OpenAI API; возвращает JSON для копирования. Python 3.10+, сторонние пакеты не требуются.

```powershell
$env:OPENAI_API_KEY = 'ваш ключ'
$env:OPENAI_MODEL = 'gpt-4o-mini' # необязательно
python app.py example.json > result.json
```

Ключ хранится только в окружении, не записывайте его в репозиторий. В `example.json` — единственный пример из задания, а не подтверждённые данные реального товара. Поля name, manufacturer, description — строки; specs — объект характеристик. Сервис проверяет вход, пустые значения, ошибки API и структуру ответа. Характеристики копируются напрямую из входа. При недостатке фактов модель должна обозначить пробелы, а не заполнять текст повторами; длина описания проверяется и показывается предупреждение.

## Промпт и решения

Системный промпт отделяет данные товара от инструкций, запрещает домысливать и задаёт структуру ответа. Низкая температура снижает вариативность; результат валидируется по форме. Программа не даёт модели формировать список технических значений, а копирует его из источника. В конце обязательна проверка специалистом: программная проверка не доказывает фактическую достоверность свободного текста.

## Ограничения и развитие

В PDF упомянуты два товара, но приведён только пример одного; для требуемых двух результатов нужны исходные данные от работодателя. Без рабочего API-ключа реальные результаты модели не демонстрируются. Нет гарантии, что модель не добавит неуказанное утверждение; для промышленного применения нужны проверка утверждений по источнику, схемы обязательных полей по типам приборов, тестовый набор, повторная генерация при ошибке формата, логирование без секретов и веб-интерфейс. Входные данные передаются выбранному API-провайдеру; не отправляйте конфиденциальные паспорта без разрешения.
