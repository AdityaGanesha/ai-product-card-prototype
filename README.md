# Черновик карточки прибора

Консольный MVP принимает JSON товара и вызывает OpenAI-совместимый API; возвращает JSON для копирования. Python 3.10+, сторонние пакеты не требуются. По умолчанию используется локальная Ollama с моделью `llama3.1:8b`.

```powershell
ollama serve # в отдельном терминале, если сервер ещё не запущен
ollama pull llama3.1:8b # один раз, если модели ещё нет
python app.py vit1.json > result.json
```

Ollama работает по адресу `http://127.0.0.1:11434/v1`, ключ ей не нужен. Для другого OpenAI-совместимого API задайте `OPENAI_BASE_URL`, `OPENAI_MODEL` и `OPENAI_API_KEY` в окружении. Ключ не записывайте в репозиторий. В `example.json` — пример из задания, а не подтверждённые данные реального товара. Поля name, manufacturer, description — строки; specs — объект характеристик. Сервис проверяет вход, пустые значения, ошибки API и структуру ответа. Характеристики копируются напрямую из входа. При недостатке фактов модель должна обозначить пробелы, а не заполнять текст повторами; длина описания проверяется и показывается предупреждение.

## Промпт и решения

Системный промпт отделяет данные товара от инструкций, запрещает домысливать и задаёт структуру ответа. Низкая температура снижает вариативность; результат валидируется по форме. Программа не даёт модели формировать список технических значений, а копирует его из источника. В конце обязательна проверка специалистом: программная проверка не доказывает фактическую достоверность свободного текста.

## Ограничения и развитие

Примеры `vit1.json` и `vit2.json` составлены по открытым карточкам товаров работодателя; источники указаны в `examples.md`. В этом файле приведены вручную подготовленные образцы ожидаемого формата. `vit1-result.json` и `vit2-result.json` — реальные ответы локальной llama3.1:8b. На этих входах описания получились короче требуемых 800–1200 символов; сервис явно предупреждает об этом, а ручные примеры показывают целевой формат. Нет гарантии, что модель не добавит неуказанное утверждение; для промышленного применения нужны проверка утверждений по источнику, схемы обязательных полей по типам приборов, тестовый набор, повторная генерация при ошибке формата, логирование без секретов и веб-интерфейс. При использовании внешнего API входные данные передаются провайдеру; не отправляйте конфиденциальные паспорта без разрешения.
